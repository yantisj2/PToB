# Independent USB integer-association witness: offline design

Copyright (c) 2026 Jonathan Yantis. MIT.

This design identifies evidence needed to resolve a device SOF label's integer
association. It implements no observer, firmware change, source correction or
clock feed. Hardware, instrumentation and installation remain deferred.

## Required independent observation

The missing evidence is the identity of the **same physical SOF event** at the
wire and at the device capture. USB SOF tokens contain an11-bit frame number;
see [Microsoft's packet description](https://learn.microsoft.com/en-us/windows-hardware/drivers/usbcon/usb-control-transfer)
and the [USB2.0 specification](https://www.usb.org/document-library/usb-20-specification).
Nordic describes FRAMECNTR as a readable free-running SOF counter and documents
16MHz synchronization before PPI in its
[USBD specification](https://docs.nordicsemi.com/r/bundle/ps_nrf52840/page/usbd.html).
That wording does not prove FRAMECNTR copies the received wire field or starts
at the host's integer origin.

For an independently bound event, let `W` be the decoded wire frame and `D` the
device label. The observed origin is `k = (W - D) mod 2048`. This is a discrete
event-identity relation, not an offset fitted from phase, UTC or the
M-HAT-disciplined clock. A nonzero `k` need not identify a device defect: it could
represent an unverified counter origin. It would show that a host interpretation
assuming a different `k` needs review. No value is automatically corrected here.

An initial or persistent integer shift can leave every device cadence check
coherent. With unknown combined physical bias, shifting a candidate frame by
one period and shifting that unknown bias oppositely can preserve the
request/host interval constraints too. More samples, a smaller residual or the
frozen provisional UTC correction do not remove this ambiguity. A UFA1 token
identifies a request and immutable reply, not an independently labeled SOF.

| Evidence | What it establishes | Remaining limit |
| --- | --- | --- |
| UTS1/UFA1 and MFINDEX brackets | Conditional cadence/origin consistency, identity, epochs and request enclosures | Integer interpretation and physical bias can remain ambiguous. |
| Exact installed source and offline interleavings | Accepted scalar combinations and source-level capture-before-status ordering | Hardware ordering and which endpoint is wrong remain unproven. |
| Independent wire SOFs and token-matched control traffic | Wire frame identities and a request's wire-domain interval | Request identity alone does not bind CC3 to one physical SOF. |
| Wire SOFs and a verified witness of the same capture event | Discrete wire/device event join, with explicit resource/order bounds | Controller/PHY phase and source UTC still need separate metrology. |

## Conditional wire-only experiment

A future separately scoped protocol observation could retain decoded SOF
packet start/end intervals, frame fields, CRC status, loss indicators and the
existing marker traffic. Match full device/enumeration scope, MCU boot,
USB/capture epochs, token, sequence and immutable response bytes. Reset,
ambiguous address reuse, packet loss or discontinuity fences the join; do not
guess frame wraps.

Under the exact installed callback's source-supported capture-before-status
order, a conservative wire bracket runs from SETUP transaction start through
its successful status handshake. Retain NAKs, retries and errors. The separate
zero-length/null-pointer finding still needs review; a sanitizer exclusion is
not a hardware-order guarantee.

If the complete bracket intersects multiple SOFs, retain all alternatives.
If it lies between decoded SOFs, the wire frame supplies a candidate logical
label, but the proof still needs a justified bound on CC3 updating relative to
that wire event. A bracket without a SOF inside is not proof CC3 has updated.
Nordic's documented synchronization provides no atomic FRAMECNTR/CC latch
guarantee. Without the required event/settling bound, classify the result
conditional or unavailable. Do not invent a near1ms age cutoff or arbitrary
guard interval from development captures. Whole OUT-to-matching-IN bounds
remain available when status ordering is unproven, even if they cannot choose
one SOF. Request/arrival midpoints never replace the original event.

## Stronger event witness and prerequisites

A stronger future experiment would observe decoded wire SOFs and a signal
demonstrably generated by the **same hardware event/task route** that latches
the reported capture. A GPIO/PPI witness is only a design candidate: no pin,
GPIOTE/PPI channel, fork or timer resource is assumed free. Separate ownership,
resource, electrical loading, exact-image and recovery review is required
before choosing or installing an implementation. No route is configured here.

The proof must establish actual event identity, register ownership, latency/order
bounds and immutable publication. A CPU callback GPIO toggle adds scheduling
delay; a pulse from a similar timer does not establish the same event. Preserve
missing/extra pulses, complete intervals and observer effects. Event counting
must survive frame wrap and epoch changes. A trace with an unverified route
does not close this term.

Even a verified integer join does not calibrate MFINDEX-to-wire, PHY, cable,
GPIO delay or UTC. Original source authority/expiry and all source/root/path/
boot/epoch fences remain separate. Coherent captures during source loss remain
nonmeasurements. The frozen−25,600ns dependent correction is never used to
decide which event label is correct.

## Validation and current limit

Predeclare future/held-out populations before inspecting results. Report every
attempt, join, structural ambiguity, rejection, warmup and failure. Test known
synthetic initial/persistent shifts, transient label and counter excursions,
wrap, packet loss, stale tokens, replay, context changes and expiry. A wrong
initial origin must fail an independent event join even when internal residuals
are zero. Keep counter-versus-label alternatives; measured false positives and
misses require independent truth. Boundary conditions must be represented, not
only middle-of-frame requests. Development records remain distinct from validation.

Reviewed stock userspace interfaces do not expose this complete witness.
Software MMIO timestamps could narrow a host-read term but still would not
decode wire SOFs or certify device capture identity. Optional controller
correlation support is unverified and does not authorize command-ring work,
probes or driver-owned memory access. The next discriminating evidence is a
reviewed independent event witness or vendor-supported association bound,
not another phase fit. See the [ledger](usb-sof-research.md) and
[coherence-repair proposal](t096-sof-association-proposal.md).
